Tổng Quan Dự Án

Dự án là một hệ thống agent tạo báo cáo ESG, tập trung vào tính kiểm toán được: mọi câu trả lời định tính phải dựa trên evidence, còn dữ liệu định lượng được xử lý bằng mapping deterministic thay vì dùng LLM.

Phạm vi chức năng

  • Tạo câu trả lời cho 95 câu hỏi ESG định tính từ template_v1/question/questions.json.
  • Áp dụng guideline theo 4 quy mô công ty và 11 nhóm ngành.
  • Gọi Team RAG endpoint mặc định /qualitative/evidence/v3 để lấy evidence.
  • Map 251 metric định lượng QUANT-0001..QUANT-0251.
  • Xuất JSON audit, coverage summary và Excel workbook.

Trạng thái hiện tại

  • API async qua Temporal là hướng vận hành chính; endpoint generate đồng bộ vẫn tồn tại nhưng đã đánh dấu deprecated.
  • Pipeline có cơ chế evidence gate, source normalization, policy critic, semantic critic, revision và output hygiene.
  • Hệ thống có fallback offline khi ESG_AGENT_MODE=auto mà thiếu API key LLM.
  • Kiểm thử hiện tại bao phủ CLI/API, RAG contract, graph offline, output writer, provenance, quantitative, Temporal và semantic/source hygiene.

프로젝트 개요

이 프로젝트는 감사 가능성을 중심에 둔 ESG 보고서 생성 agent 시스템입니다. 정성 답변은 evidence 기반이어야 하며, 정량 데이터는 LLM이 아닌 deterministic mapping으로 처리됩니다.

기능 범위

  • template_v1/question/questions.json의 95개 정성 ESG 질문 답변 생성.
  • 4개 회사 규모와 11개 산업군 guideline 적용.
  • 기본 Team RAG endpoint /qualitative/evidence/v3 호출.
  • 251개 정량 지표 QUANT-0001..QUANT-0251 매핑.
  • JSON audit, coverage summary, Excel workbook 출력.

현재 상태

  • Temporal 기반 비동기 API가 권장 운영 경로이며, 동기 generate endpoint는 deprecated 상태입니다.
  • pipeline은 evidence gate, source normalization, policy critic, semantic critic, revision, output hygiene를 포함합니다.
  • ESG_AGENT_MODE=auto에서 LLM API key가 없으면 offline fallback을 사용할 수 있습니다.
  • 현재 테스트는 CLI/API, RAG contract, offline graph, output writer, provenance, quantitative, Temporal, semantic/source hygiene를 포괄합니다.

Quy Trình Xử Lý

Pipeline LangGraph hiện có 15 node. Luồng đi tuyến tính tới semantic review, sau đó có vòng lặp revision nếu còn lỗi và chưa vượt giới hạn ESG_MAX_REVISION_ROUNDS.

1
Normalize Company Input
Validate identifier, năm, scale, industry, top_k, run_id và output language.
2
Select Template + Plan Questions
Load template 95 câu hỏi, chọn subset theo item_ids, merge guidance theo quy mô/ngành.
3
Retrieve RAG Evidence
Gọi Team RAG theo batch size mặc định 20, concurrency mặc định 4, top_k mặc định 5.
4
Evidence Gate + Normalization
Chỉ giữ câu có evidence hợp lệ, semantic label dùng được, source path đầy đủ và contract v3 không vi phạm nghiêm trọng.
5
Quantitative Processing
Map 251 metric từ file/API; metric có match được bridge vào câu qualitative dạng Metrics.
6
Skill Selection + Context
Router chọn skill chuyên môn, context builder gom question, guideline, evidence, source và quality flags.
7
Draft + QA + Semantic Review
Writer tạo draft, policy critic chặn claim không có evidence, semantic critic kiểm tra facet/alignment/source usage.
8
Revision + Hygiene + Assembly
Draft fail có evidence được revise tối đa 2 vòng mặc định; output hygiene chuẩn hóa Markdown/PII rồi report manager đóng gói artifact.

API job lifecycle

Đường async: POST /reports/esg/qualitative/jobs trả 202, người dùng polling GET /jobs/{job_id}, lấy kết quả qua GET /jobs/{job_id}/result, hoặc hủy bằng DELETE /jobs/{job_id}. Temporal activity heartbeat theo từng node để job dài hạn vẫn quan sát được.

처리 프로세스

현재 LangGraph pipeline은 15개 node로 구성됩니다. semantic review까지 선형으로 진행한 뒤, 오류가 있고 ESG_MAX_REVISION_ROUNDS 한도 내이면 revision loop를 수행합니다.

1
Normalize Company Input
identifier, year, scale, industry, top_k, run_id, output language 검증.
2
Select Template + Plan Questions
95개 질문 template load, item_ids subset 선택, 규모/산업 guidance 병합.
3
Retrieve RAG Evidence
기본 batch size 20, concurrency 4, top_k 5로 Team RAG 호출.
4
Evidence Gate + Normalization
유효 evidence, 허용 semantic label, source path, v3 contract를 기준으로 answer 가능 항목만 통과.
5
Quantitative Processing
file/API에서 251개 metric을 매핑하고, match된 metric을 Metrics 유형 qualitative QID에 bridge.
6
Skill Selection + Context
router가 전문 skill을 선택하고 context builder가 question, guidance, evidence, source, quality flags를 구성.
7
Draft + QA + Semantic Review
writer가 draft를 만들고 policy critic은 근거 없는 claim을 차단하며 semantic critic은 facet/alignment/source usage를 검사.
8
Revision + Hygiene + Assembly
evidence가 있는 failed draft는 기본 최대 2회 revise되고, output hygiene 후 report manager가 artifact를 조립.

API job lifecycle

비동기 경로는 POST /reports/esg/qualitative/jobs가 202를 반환하고, 사용자는 GET /jobs/{job_id}로 상태를 polling하며, GET /jobs/{job_id}/result로 결과를 받고, DELETE /jobs/{job_id}로 취소할 수 있습니다. Temporal activity는 node별 heartbeat를 보내 장기 job 관찰성을 제공합니다.

예상 성능 병목

  • 전체 지연 시간은 Team RAG와 LLM에 크게 의존합니다. 내부 graph 작업은 주로 validation, mapping, file writing입니다.
  • Semantic QA concurrency 기본값 4는 review 병렬성을 제공하지만 LLM provider 처리량에 의해 제한됩니다.
  • Excel output은 audit column과 긴 evidence 텍스트가 많아 full 95문항에서는 I/O 비용이 커질 수 있으나 atomic write가 적용되어 있습니다.
  • 정량 251개 metric은 deterministic mapping이라 안정적이고 빠르며 LLM token 비용이 발생하지 않습니다.
